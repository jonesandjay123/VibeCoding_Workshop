## Block 2 ▸ JSON：電腦看的 .md
**⏰ 0:40 – 1:10 ｜ 能量：穩定上升**

### 🎯 目標
- 理解 JSON 是結構化資料格式
- 能看懂一段 JSON
- 自己設計打卡紀錄的 JSON 結構

### 📋 具體步驟

#### Part A — JSON 是什麼（0:40 – 0:50）
1. 接著剛才她列的四項資料，問：

> 💬 **關鍵句：**「你剛剛說要存日期、單字數、英文句子、連續天數。如果你要傳這些資料給一個朋友，你可能會用 Line 打一段文字對吧？但如果你要傳給電腦呢？電腦需要一種『有規則的格式』才看得懂。這就是 JSON。」

2. 展示三種格式的比較：

**純文字（.txt）：**
```
2026年2月27日 學了10個單字 I will study every day. 連續3天
```

**Markdown（.md）：**
```
## 打卡紀錄
- 日期：2026-02-27
- 學了：10 個單字
- 句子：I will study every day.
- 連續：3 天
```

**JSON：**
```json
{
  "date": "2026-02-27",
  "words_learned": 10,
  "sentence": "I will study every day.",
  "streak": 3
}
```

3. 比較三者：

> 💬 **關鍵句：**「.txt 是給你看的隨意筆記，.md 是給你看的有格式筆記，JSON 是給電腦看的有格式筆記。JSON 就像是『電腦看的 Markdown』。」

4. 強調規則：
   - 用 `{ }` 包住
   - 每一項都是 `"key": value`（鑰匙 : 值）
   - 文字要用引號，數字不用
   - 項目之間用逗號

#### Part B — 打開 Demo 1：JSON 視覺化（0:50 – 0:58）
5. 打開 `demo-1-json-viewer.html`
6. 讓她看到打卡資料的 JSON 被視覺化顯示
7. 試著改 JSON 裡面的值 → 看到畫面即時更新

> 💬 **關鍵句：**「你看，左邊是 JSON 原始碼，右邊是人類看的版本。同一份資料，不同的呈現方式。」

8. 指著 JSON 問她：
   - 「`words_learned` 是什麼？」→ 「學了幾個單字」
   - 「如果妹妹今天學了 15 個，你要改哪裡？」→ 她指出 `10` 改成 `15`

#### Part C — 她自己設計 JSON（0:58 – 1:05）
9. 問她：

> 💬 **關鍵句：**「如果你覺得這個打卡紀錄不夠，你想加什麼？」

10. 讓她自己想，可能會說：
    - 心情 → `"mood": "😊"`
    - 花了多少分鐘 → `"minutes": 30`
    - 學的單字列表 → `"words": ["apple", "banana"]`（陣列！）
11. Jones 引導她加進去：

```json
{
  "date": "2026-02-27",
  "words_learned": 10,
  "sentence": "I will study every day.",
  "streak": 3,
  "mood": "😊",
  "minutes": 30
}
```

> 💬 **關鍵句：**「你剛剛設計了一個資料結構。工程師每天也在做一樣的事——想清楚要存什麼資料、長什麼樣子。」

#### Part D — 為什麼要結構化（1:05 – 1:10）
12. 問她：

> 💬 **關鍵句：**「如果妹妹用了一個月，有 30 筆打卡紀錄。你想看『哪一天學最多單字』——用 .txt 怎麼找？用 JSON 呢？」

13. 讓她感受差異：
    - .txt → 要自己一行一行看
    - JSON → 電腦可以直接幫你比較 `words_learned` 的數字
14. 總結：

> 💬 **關鍵句：**「結構化 = 電腦看得懂 = 可以幫你自動做很多事。這就是為什麼所有 APP 都用 JSON 而不是純文字。」

### 🎭 預期學生反應
- .txt/.md/JSON 三格比較會很直觀
- 自己設計 JSON 結構時會很投入（「加心情 emoji！」）
- Demo 1 即時更新會覺得有趣
- 可能會問「陣列是什麼？」→ 簡單帶過「就是一個清單，用方括號」

### ✅ 成就感 Moment
> 「我設計了自己的 JSON 資料結構！」

## Block 3 ▸ localStorage + DevTools：資料活起來了！
**⏰ 1:10 – 1:50 ｜ 能量：高峰 🔥**

### 🎯 目標
- 理解 localStorage = 瀏覽器裡的小抽屜
- 在 DevTools 裡親眼看到資料
- 體驗「刷新頁面資料還在」的神奇時刻
- 理解 JSON.stringify / JSON.parse

### 📋 具體步驟

#### Part A — localStorage 概念（1:10 – 1:18）
1. 回到剛才的三層圖，指著 Data 層：

> 💬 **關鍵句：**「資料要存在哪裡？真實產品會存在伺服器的資料庫裡。但我們今天用一個更簡單的方法——把資料存在瀏覽器裡面。瀏覽器有一個『小抽屜』叫 localStorage，你可以把東西放進去，關掉瀏覽器再打開，東西還在。」

2. 用抽屜比喻加強：

```
🗄️ localStorage = 你書桌的抽屜

  放東西進去：  localStorage.setItem("key", "value")
  拿東西出來：  localStorage.getItem("key")
  清空抽屜：    localStorage.clear()

  📌 限制：只能存文字（字串）
  📌 所以 JSON 物件要先「變成文字」才能存
```

> 💬 **關鍵句：**「localStorage 就像你書桌的抽屜。你把筆記紙放進去，明天打開抽屜，紙還在那裡。但抽屜只能放紙（文字），不能放真的東西（物件），所以你要先把東西『寫在紙上』——這就是 JSON.stringify。」

#### Part B — 打開 Demo 2：打卡頁面！（1:18 – 1:30）
3. 打開 `demo-2-checkin-basic.html`
4. 讓她操作：
   - 輸入今天學了幾個單字
   - 寫一句英文
   - 按「打卡」按鈕
5. 看到打卡成功、連續天數 +1

> 💬 **關鍵句：**「你剛打卡了。資料現在存在哪裡呢？我們來偵探一下。」

#### Part C — DevTools 大發現（1:30 – 1:40）🔥
6. **這是今天最重要的時刻！**
7. 按 F12（或 Cmd+Option+I）打開 DevTools
8. 點 **Application** 標籤
9. 左邊找到 **Local Storage** → 展開
10. 她會看到剛才的打卡資料！

> 💬 **關鍵句：**「看到了嗎！你剛剛打卡的資料就在這裡！你可以看到 key 是什麼、value 是什麼。這就是你的資料，存在瀏覽器的小抽屜裡。」

11. 讓她看 value 的內容——是一段 JSON 字串！
12. 點擊 value 展開看：

> 💬 **關鍵句：**「你看，這就是你剛剛學的 JSON 格式！date、words_learned、sentence、streak——跟你設計的一模一樣。資料從輸入框 → JavaScript → JSON → localStorage，這就是資料流動的過程。」

#### Part D — 刷新大實驗（1:40 – 1:45）
13. **關鍵體驗：**

> 💬 **關鍵句：**「現在，你按 F5 重新整理頁面。」

14. 她重新整理——**資料還在！** 連續天數還在！
15. 回到 DevTools → Application → Local Storage → 資料也還在

> 💬 **關鍵句：**「🎉 看到了嗎？刷新頁面，資料沒有消失！因為 localStorage 是真的存在你的電腦裡的。上次 Session 2 的 Todo demo，重新整理就消失了，記得嗎？那是因為沒有存。今天你的打卡紀錄不會消失了。」

16. 對比：
    - Session 2 的 Todo → 不會存 → 刷新就沒了
    - 今天的打卡 → 存了 localStorage → 刷新還在

#### Part E — JSON.stringify / JSON.parse 觀察（1:45 – 1:50）
17. 在 DevTools 的 Console 裡打：
    ```js
    localStorage.getItem("checkin-records")
    ```
18. 看到的是一段「文字」（有引號）
19. 再打：
    ```js
    JSON.parse(localStorage.getItem("checkin-records"))
    ```
20. 看到的是一個「物件」（可以展開）

> 💬 **關鍵句：**「`JSON.stringify` = 把東西寫在紙上（物件 → 文字）。`JSON.parse` = 把紙上的字讀回來（文字 → 物件）。因為 localStorage 的抽屜只能放紙（文字），所以存的時候要 stringify，拿出來要 parse。」

21. 快速帶到限制：

> 💬 **關鍵句：**「localStorage 很方便，但它是學習用的資料庫。真實產品——像 IG、Line——會把資料存在伺服器上，這樣你換手機也能看到。localStorage 只存在這台電腦的這個瀏覽器裡。但作為學習工具，它超棒的。」

### 🎭 預期學生反應
- 打卡頁面本身會讓她很開心（「這就是我想做的東西！」）
- **DevTools 看到資料的瞬間** → 「哦哦哦！真的存在這裡！」（今天的最高潮！）
- 刷新後資料還在 → 驚訝 + 滿足
- Console 裡打指令可能會有點緊張 → Jones 引導她一步一步來
- stringify/parse 的比喻（紙/物件）很好記

### ✅ 成就感 Moment
> 「我在 DevTools 裡看到我的資料了！刷新還在！」🎉（今天的最高潮）

## Block 4 ▸ Git Branch：平行宇宙體驗
**⏰ 2:00 – 2:40 ｜ 能量：回升 → 穩定**

### 🎯 目標
- 理解 Branch = 平行宇宙
- 體驗切換 branch 時檔案出現/消失的魔法
- 完成 merge 回 main
- 用 git log 看時間軸

### 📋 具體步驟

#### Part A — Branch 概念（2:00 – 2:08）
1. 回到電玩存檔比喻：

> 💬 **關鍵句：**「上次學的 Git 像是存檔。今天要學一個更厲害的——Branch，分支。你有沒有玩過那種『選擇會影響結局』的遊戲？在某個選擇點，你可以存檔，然後試試看 A 路線，不喜歡就回到存檔點走 B 路線。Branch 就是這個——平行宇宙。」

2. 畫個簡單的圖：

```
         ★ 建 branch
main ─────●──────────────────── main（安全的原版）
           ╲
            ╲─── ● ─── ● ──── feature（實驗區）
                加JSON   改UI
```

> 💬 **關鍵句：**「main 是你的正式版、安全版。Branch 是你的實驗室。在實驗室裡搞砸了，main 不會受影響。實驗成功了，再合併回 main。」

#### Part B — Jones 準備好的 repo（2:08 – 2:12）
3. Jones 事先在 repo 裡準備好一個簡單的打卡頁面（main branch）
4. 讓她 `git pull` 拉最新版：
   ```
   cd ~/Desktop/azunyan.hp
   git pull
   ```
5. 確認現在在 main branch：
   ```
   git branch
   ```

> 💬 **關鍵句：**「`git branch` 會告訴你『你現在在哪個宇宙』。星號在 main → 你在正式版。」

#### Part C — 建立 Branch + 做改動（2:12 – 2:22）
6. 建立新 branch：
   ```
   git checkout -b feature-json-storage
   ```
7. 再看一次 branch：
   ```
   git branch
   ```
8. 星號移到 `feature-json-storage` 了！

> 💬 **關鍵句：**「你剛剛建了一個平行宇宙，叫做 feature-json-storage。你現在在這個實驗室裡面。」

9. 把 demo-2 的打卡頁面（或簡化版）加到專案裡
10. 正常 git 流程：
    ```
    git add .
    git commit -m "加入打卡功能（localStorage 版）"
    ```

> 💬 **關鍵句：**「你在 branch 裡加了新功能。現在，我們來看看 main 會怎樣——」

#### Part D — 切換的魔法！（2:22 – 2:30）🔥
11. **魔法時刻！**
    ```
    git checkout main
    ```
12. 讓她打開 Finder 看——**打卡檔案消失了！**

> 💬 **關鍵句：**「看到了嗎！你切回 main，打卡的檔案不見了！因為 main 宇宙裡根本沒有這個功能。」

13. 再切回去：
    ```
    git checkout feature-json-storage
    ```
14. **打卡檔案又回來了！**

> 💬 **關鍵句：**「切回 branch，檔案又出現了！這就是平行宇宙。兩邊互不影響。這就是為什麼工程師都用 branch 做新功能——搞砸了不怕，main 永遠安全。」

15. 如果她覺得神奇，可以多切幾次讓她體驗

#### Part E — Merge + git log（2:30 – 2:40）
16. 實驗成功了，合併回 main：
    ```
    git checkout main
    git merge feature-json-storage
    ```
17. 現在 main 也有打卡功能了！

> 💬 **關鍵句：**「你把實驗室的成果正式搬進 main 了。以後你做任何新功能，都可以開一個 branch 來做，安全又乾淨。」

18. 看時間軸：
    ```
    git log --oneline
    ```
