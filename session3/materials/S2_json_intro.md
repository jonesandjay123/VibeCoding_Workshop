# S2：JSON 教學腳本 — 電腦看的 Markdown

> **對應 Block 2（0:40 – 1:10）**  
> **核心概念：** JSON 是結構化資料格式，讓電腦能讀懂你的資料

---

## 🎯 教學目標

學完這段，她能：
1. 看懂一段 JSON
2. 說出「JSON 是結構化資料」
3. 自己設計一個簡單的 JSON 結構

---

## 📖 教學流程

### Step 1：為什麼需要結構

從 Block 1 的需求拆解接續。她已經列出了打卡要存的資料（日期、單字數、句子、連續天數）。

> 💬 Jones：「你剛剛列了四項資料。如果你用 Line 告訴我這些，你會怎麼打？」

讓她打一段，大概會是：
```
今天2/27，學了10個單字，I will study every day.，連續3天
```

> 💬 Jones：「這段話你看得懂，但電腦看不懂。電腦不知道『10』是單字數還是連續天數。所以我們需要一種有規則的格式。」

---

### Step 2：三格比較

展示同一份資料的三種格式：

| 格式 | 給誰看 | 特色 |
|------|--------|------|
| `.txt` 純文字 | 人 | 隨意，沒有規則 |
| `.md` Markdown | 人 | 有格式、有標題，但電腦不好解析 |
| `.json` JSON | 電腦（人也能看） | 嚴格規則，電腦秒懂 |

> 💬 Jones：「JSON 就像是『電腦看的 Markdown』。人類看 Markdown 覺得清楚，電腦看 JSON 覺得清楚。」

---

### Step 3：JSON 語法四規則

用打卡紀錄教：

```json
{
  "date": "2026-02-27",
  "words_learned": 10,
  "sentence": "I will study every day.",
  "streak": 3
}
```

| 規則 | 說明 | 例子 |
|------|------|------|
| `{ }` 包住 | 整份資料用大括號 | 最外面的 `{ }` |
| `"key": value` | 每一項是「名稱: 值」 | `"date": "2026-02-27"` |
| 文字要引號 | 字串用雙引號包 | `"2026-02-27"` |
| 數字不用引號 | 數字直接寫 | `10`、`3` |

> 💬 Jones：「就四個規則。大括號、冒號、文字要引號、數字不用。就這樣。」

---

### Step 4：Demo 1 體驗

打開 `demo-1-json-viewer.html`：
- 左邊顯示 JSON 原始碼
- 右邊顯示視覺化的卡片
- 改左邊的值 → 右邊即時更新

讓她試：
- 把 `10` 改成 `20` → 「學了 20 個單字」
- 把 emoji 改一下 → 看到視覺化也變了

---

### Step 5：她自己設計

> 💬 Jones：「如果你覺得這四項不夠，你想加什麼？」

引導方向：
- 心情 → `"mood": "😊"`
- 花的時間 → `"minutes": 30`
- 單字清單 → `"words": ["apple", "banana"]`（帶出陣列概念）
- 是否完成目標 → `"goal_met": true`（帶出布林值）

> 💬 Jones：「你剛剛做的事情叫『設計資料結構』。工程師每天都在做這個。」

---

### Step 6：為什麼要結構化

> 💬 Jones：「如果妹妹用了一個月，30 筆紀錄。你想看『哪天學最多』——用 .txt 要自己一行一行找。用 JSON？電腦直接幫你比。」

重點：**結構化 = 電腦看得懂 = 可以自動處理**

## 📎 補充資料

### JSON 值的類型（只需口頭帶過）
| 類型 | 例子 | 說明 |
|------|------|------|
| 字串 | `"hello"` | 文字，要雙引號 |
| 數字 | `42` | 不用引號 |
| 布林 | `true` / `false` | 是/否 |
| 陣列 | `["a", "b"]` | 一個清單 |
| null | `null` | 「沒有」 |
