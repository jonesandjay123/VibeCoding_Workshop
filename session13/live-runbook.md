# Session 13 导师手册：先听懂问题，再选一个例子

这份手册帮你临场判断，不要求你按页讲完。Session 12 没有实际上课，不预设学生已懂 Python、Pandas、选图或工具设定。

## 先记住三件事

1. 先看她最近真正使用的数据与作业。不要一开场就叫她跑教材。
2. 每次只问一个问题、做一个动作。看完结果，再说原因。
3. 本次只处理一个主要问题。素材库是用来补卡点，不是上课进度表。

## 00–20 分钟：了解她现在在哪里

可以这样开场：

「你最近用 Codex 做了什么？先打开给我看看。今天不用把这份 notebook 全部跑完，我们先找一件你最想弄懂或完成的事。」

依序问，上一题还没回答完，不要一口气补四个问题：

- 「这份作业要你做什么？」请她指题目，不急著看代码。
- 「你现在做到哪一步？」请她示范已经能完成的部分。
- 「接下来是哪里卡住？」让她指出一个具体画面、数字或错误。
- 「今天结束前，你最希望哪件事能变清楚？」

第 15–20 分钟，整理成一句话让她确认。例如：

「今天先弄清楚这张图上的数字怎么算出来。结束时，你能挑一根柱子，从原始数据重新算一次。」

这只是例子，不要替她决定题目。若她不方便分享文件，请她口述问题和字段；用合成数据示范相同概念，不要求上传原件。

## 共用的 120 分钟时间框架

| 时段 | 用途 |
| :--- | :--- |
| 00–20 | 看实际作业、了解目标、选一个问题 |
| 20–30 | 确认最小环境，选支线 A、B 或 C |
| 30–55 | 一起做选定问题的第一步 |
| 55–60 | 休息 |
| 60–85 | 继续同一个问题，核对结果 |
| 85–100 | 她自己操作一小步，或说明一个改动 |
| 100–105 | 机动时间；若前面已借用，就不再追加 |
| 105–115 | 保存并重跑本次选定的分析 |
| 115–120 | 回顾成果与仍需要的帮助 |

三条支线只是不同路线，总长都仍是 120 分钟。超时时缩小题目或取消进阶内容，保留休息与最后的核对。

## 20–30 分钟：确认最小环境

先依今天选定的问题，只检查会用到的环境。

如果走支线 A，先在目前的 Python kernel 执行 `print(1 + 1)`，看到 2 就可以开始 cell 与变量的实验；这条支线不需要先安装 pandas 或 matplotlib。

如果要用 Pandas 看表或分析，再执行 workbook 模块 0 的环境格，看它显示的 Python 路径。若只是口头核对现有结果，也不用为了教材而先安装新套件。

如果出现 `ModuleNotFoundError: No module named 'pandas'`，意思是**这个 kernel 使用的 Python 找不到 pandas**，不是数据坏了。先确认选了哪个 Python；新建 `.venv` 不会自动带有分析套件。需要安装时，请工具针对这个环境处理，完成后再跑环境格。

环境格成功只代表这一步成功，不能因此说整份 notebook 都测过了。AI 的「已安装」也要用实际 import 结果确认。

环境排查最多额外借 5 分钟机动时间。仍不通就用导师已确认可用的环境；课中先完成理解与验证，学生端重跑留待补做。

## 支线 A：她不明白 cell 与 kernel 怎么执行

**何时选这条：** 她问「为什么上面改了，下面没变？」或「为什么重跑后数字不一样？」

先用一句话说明：「每个代码格会把指令交给同一个 Python 程序。这个程序叫 kernel，它记得刚才的变量。Notebook 不会因为你修改上面的格子，就自动从上到下重算。」

另开一份不含私人数据的 scratch notebook。不要在她原来的作业上做删格实验。

### 第一步：重跑「设定值」

在一个代码格输入：

```python
x = 10
print(x)
```

请她执行一次，再执行一次。两次都应显示 `10`。

原因：`x = 10` 每次都把 x 设成 10。它没有在原来的值上增加什么。

### 第二步：重跑「在原值上加一」

新增下一个代码格：

```python
x = x + 1
print(x)
```

先问：「现在 x 是 10，这一格跑一次会变成多少？」执行后应显示 `11`。只再跑这一格，应显示 `12`。

原因：右边先读取目前的 x，再加 1，最后把结果存回 x。这一格依赖 kernel 里目前的值。

### 第三步：看出画面顺序不等于自动更新

回去只跑第一格。它把 x 设回 `10`，但第二格下面先前显示的 `12` 仍可能留在画面上。

新增一格，只写 `print(x)`，现在应显示 `10`。旧输出是一张先前结果的纪录，不是会自动更新的仪表板。

如果这样已经解答她的问题，就回到她的作业，不必再做下面延伸。

### 需要时才补：删格与重启

在上述步骤完成后，删掉前两个赋值格，保留 `print(x)`。只执行它，仍应显示 `10`，因为删除文件中的代码不会清掉 kernel 的记忆。

接著**只重启 kernel，不要全部执行**。再跑 `print(x)`，应出现 `NameError`，因为新的 kernel 还不知道 x 是什么。

最后在 `print(x)` 上方补回 `x = 10`。重启后依序全部执行，应显示 `10`。这次不会报错，因为前面的格子重新定义了 x。

**检查理解：** 请她指出，自己的作业需要先跑哪一格、哪一个旧输出应该重算。不要把整段实验背出来当成验收。

## 支线 B：她不清楚表格如何变成答案

**何时选这条：** 程序能跑，但她不明白 `shape`、筛选或加总的意思。

先问：「这份数据的一行代表什么？」如果不能回答，先一起看原表；不要立即讲 `groupby`。

依卡点选一段，不必全部讲：

- **看表。** Workbook 模块 1：`shape` 告诉你整张表有 20 行、5 栏；`head()` 只预览前 5 行，没有删掉后面的 15 行。
- **筛行。** 模块 4：从原本 20 行留下 `profit > 20` 的 9 行。画面只列出店、年、利润 3 栏，是另外做了「选栏」，不代表筛选会自动删栏。
- **分组加总。** 模块 5：先单独看 A 店的 5 行，再把 18、22、25、30、35 相加，得到 130。四家店都做同样的事，20 行就变成 4 个总数。

一次只做目前需要的操作。`pd` 是 pandas 的简称、`df` 是变量名；她问到再解释。Series、双括号、dtype、assert 都有小抄可查，不需要先通过这些名词才能继续。

**检查理解：** 请她用自己的数据或合成例子说明：「留下了哪些行？合并了哪些行？答案的单位是什么？」只问与这次选题相关的一题。

## 支线 C：AI 做出了结果，但她不知道是否正确

**何时选这条：** 她已经有图或表，却不知道怎么验证。

先请她用一句话说题目要回答什么，再看 AI 实际用了哪张表。

例子：题目要「2025 年各店利润」，AI 却对全部 20 行按店加总。图能正常产生，但它回答的是「五年总和」。这叫问题和计算方式不一致，不是语法错误。

依序核对：

1. 先看年份：是不是只留下题目要的期间？
2. 再挑一个数字：它来自哪些原始行？用计算机或心算核对一次。
3. 最后看图：标题和单位是否符合刚才那张结果表？

若缺少某个操作概念，才借用 workbook 里相应的模块解释。不要因为图已经画好了，就跳过中间表；也不要每次都叫 AI 整份重写。

**检查理解：** 她能指出至少一项具体证据，说明结果回答了问题。不是只说「AI 说它对」。

## 85–120 分钟：完成一小步，诚实收尾

85–100 分钟，请她自己做一个与目标相关的小动作。例如换成年份 2024、修正一个筛选条件，或指出应该先执行哪个 cell。先让她说预期有什么变化，再执行；不用为每行代码做预测。

105–115 分钟，保存本次选定的分析。若使用 workbook，只重跑本次用到的模块和列明的前置步骤；不要临时把没教过的内容全跑一遍。需要完整交付时，可另存一份精简 notebook，保留必要代码与说明，从干净 kernel 顺序重跑。真实数据与成果保留在合适的私人位置。

有图就打开新输出的图片，检查标签与数字；本次目标只有理解或得到一张表，就不强迫交 PNG。

最后 5 分钟问：「今天哪件事比较清楚了？」再问「还有哪一步需要下次帮忙？」根据实际成果记录独立完成、提示后完成或待补，不用固定考卷评分。

## 语音协作：把当下情况说清楚

助手不会自动看到导师的 Zoom 或学生的画面。导师可用以下方式请求即时帮助：

「她现在想知道＿＿。画面上这格是＿＿，刚刚执行后显示＿＿。她不懂的是＿＿。请先给我一句白话说法，再给一个可以问她的小问题。」

可以用手机语音协助，同时在电脑上进行 Zoom，但这不代表助手加入了 Zoom，也不代表能直接取得系统音讯。环境声可能有回音或杂讯，导师转述或截图较可靠；视需要暂停或分段通话，不预设连续通话的时长。

只提供必要的代码或已去识别的截图。要传真实作业或学生数据前，先确认她同意及分享范围。语音协助以解释当下卡点为主，不假定助手已看到画面或知道最新执行状态。

## 课中临时修改与更新教材

1. 先说明要改哪一段、目前预期行为和希望改善什么。一次只改一个小问题。
2. 导师先继续教可进行的部分。修改、测试与推送需要时间；请等到明确的 commit／已推送确认。
3. 更新本机前先保存 notebook，确认本机所在分支及 `git status`。未保存的格子不一定会出现在 Git 状态里。
4. 若有本机修改，先保留副本并比较；需要时把新版下载到另一个文件夹。不要用 reset、force 或覆盖方式丢掉课中内容，也不要盲目在未保存的 notebook 上 pull。
5. 确认本机工作区干净、分支正确后，才使用 `git pull --ff-only`。如果它失败，停下来查看分歧，不强制更新。
6. 重新打开或重新载入新版前，先确认已保留本机内容；之后重跑必要的前置格。下载新版不会自动更新正在执行的 kernel。

本机新建的 `.venv` 或安装的套件，不是教材内容变更，不加入 repo。也不因为要同步教材，就把私人作业和旧输出一起提交。
