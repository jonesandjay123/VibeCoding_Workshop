## 15–35：Jupyter 狀態實驗

5 分鐘講 notebook／cell／kernel（見小抄），10 分鐘動手，5 分鐘教回來。**以下實驗另開 scratch notebook**，避免把故意報錯或刪格留進正式 workbook。

建立三個「真的可執行」代碼格：

```python
# Cell A
x = 10
```

```python
# Cell B
x = x + 5
print(x)
```

```python
# Cell C
print(x)
```

每一步先讓她猜，再點按；不要偷跑其他格：

| 步驟 | 操作 | 預期與原因 |
| :--- | :--- | :--- |
| 1 | 從乾淨 kernel 依序跑 A、B、C | B 和 C 都印 15 |
| 2 | 把 B 改為 `x = x + 100`，只重跑 B | 115；kernel 中原本已是 15 |
| 3 | 再跑一次 B | 215；重跑會再次改變狀態 |
| 4 | 刪除 B，只跑 C；保留 A 但不跑它 | 215；刪格沒清記憶體 |
| 5 | **只 Restart Kernel，不 Run All**，只跑 C | `NameError`；新的 kernel 還沒執行 A |
| 6 | 保留 A、C，**Restart Kernel 然後 Run All** | 10；A 重新定義了 x，所以此處不是 NameError |

若順序跑亂，回到第 1 步，還原 B 後開始。Scratch 中的 `NameError` 是故意觀察，不要把它當成正式成品的通過狀態。

追問：「剛才刪掉的是檔案裡的代碼，還是 kernel 中的值？只 Restart 和 Restart＋Run All 差在哪？」

`[*]` 通常代表忙碌；`[3]` 是執行計數，不是第 3 行或成功保證。保存過的輸出可能是舊的，空白也可能是被清除過。**改過代碼而沒跑，下方輸出不會跟著更新。**

## 35–55：讀、看、選、篩

切回正式 workbook，使用其前四個動作。節奏固定：中文需求 → 先猜形狀／行數 → 小段代碼 → 跑 → 說明結果。

- 35–40：讀 CSV；先問「一行是什麼？單位呢？」20 行 5 欄，一店一年，金額萬元。說明 `category` 不是品類明細。
- 40–45：看 `head`、`shape`、`dtypes`、缺值及重複店年。`head` 只看前五行，不能證明全表沒有缺值。
- 45–49：比較 `df['profit']` 與 `df[['profit']]`，前者 Series，後者一欄 DataFrame。Index 是標籤，篩選後不一定連號。
- 49–55：`profit > 20`。她用 CSV 數出 A 四行＋C 五行＝9 行。改成 `>= 20` 仍是 9，因樣本沒有 20；別把看似合理的直覺當驗證。

**過關：** 她能指出選欄與篩行不同，並親手改一個條件。若卡住，提示欄位／運算子，不直接貼完整答案。

## 60–80：分組、手算、畫圖

- 60–65：先問「我要每家店五年總和，結果應有幾行？年份還在嗎？」→ 4 組，年份被合併。
- 65–72：執行 `groupby('store')['profit'].sum()`；手算 A：18＋22＋25＋30＋35＝130。抽查 B＝71，再核對分組結果合計＝原表合計＝456。只對上一格不能證明整份分析正確。
- 72–80：把同一份已核對的統計表畫成條形圖。先問學生「比較還是趨勢？」看標題、年份範圍、萬元單位和條形高度；保存並打開 PNG。

**辨錯題：** 「現在有四個五年總數，可以直接畫出五年的趨勢嗎？」不行，逐年資料已被合併。排序只改順序，不創造新的統計量。

## 80–100：學生獨立改題

先遮住前面的解法；學生可查小抄、向 Codex 要提示，但不能一次要整題答案。

**必做（約 12 分鐘）：** 比較 2025 年四家門店的利潤，先印表，再畫條形圖，輸出 `outputs/profit-2025.png`，附一句以萬元為單位的解讀。先篩 `year == 2025`，別沿用五年總和冒充單年。

**進階（餘下約 8 分鐘）：** 2021–2025 年四家門店利潤趨勢，保留 `year` 與 `store`，年份由小到大，四條線各五個點。輸出 `outputs/profit-trend.png`；追問 B 店是不是每年都成長？

卡住 3 分鐘才介入，先問「哪一張中間表才是這題要畫的？」有餘力就讓她把必做題改成 2024，預測答案後親手改年份，不新增工具或新題材。
