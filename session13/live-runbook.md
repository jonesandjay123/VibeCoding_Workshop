## 階段步驟與實作指引

### Phase 1：她當小老師（00–15 min）

- [ ] 她分享螢幕，展示用 Codex 做的作業（圖＋代碼）。
- [ ] 問三個診斷問題（見開場話術），**認真聽，不要打斷**。
- [ ] 診斷重點記錄下來（心裡記）：
  - 她的需求描述是具體的（「畫各門店利潤條形圖」）還是模糊的（「幫我分析一下」）？
  - 她有驗算習慣嗎？還是 Codex 跑出來就信了？
  - 她的卡點在哪？（大概率：不知道代碼在幹嘛／不知道怎麼改／不知道對不對）
- [ ] 肯定她的成果：「妳已經會指揮 AI 做事了，今天我們把『驗算』和『理解』這兩塊補上。」

### Phase 2：Jupyter 心智模型（15–45 min）

**講解（10 分鐘）：三個概念，一個比喻**

```text
「Jupyter 不是編輯器，它是一本實驗記錄本。

- Notebook＝整本記錄本
- Cell＝一個一個小格子，寫一段代碼或文字
- Kernel＝在背後真正跑 Python 的大腦

關鍵：Cell 只是送指令的窗口，Kernel 才是執行者。
你以為刪掉一個 cell 就沒事了？它的變數還活在 Kernel 裡面。
記住這句話，接下來的坑就全懂了。」
```

**動手踩坑（20 分鐘）：她親手跑這 5 個 cell**

```python
# Cell 1
x = 10
```

```python
# Cell 2
x = x + 5
print(x)   # 猜猜印出多少？→ 15
```

```python
# Cell 3：先把 Cell 2 的 x = x + 5 改成 x = x + 100，但不要跑 Cell 1
# 然後只跑 Cell 3（跳過 Cell 1）
# 猜猜印出多少？→ 115，不是 110！因為 Kernel 裡的 x 還是 15
```

```python
# Cell 4：刪掉 Cell 2 和 Cell 3，new 一個 cell 只寫 print(x)
# 猜猜印出多少？→ 115！刪掉 cell 不等於刪掉變數
```

```python
# Cell 5：Kernel → Restart & Run All，再 print(x)
# → NameError！這才是乾淨的狀態
```

- [ ] 每個 cell 跑之前，**先讓她猜結果**，再跑。猜錯的瞬間就是學習的瞬間。
- [ ] 踩完坑，帶她看 `[*]`（正在跑）vs `[3]`（第 3 個跑完的）vs 沒有數字（還沒跑過）。
- [ ] **驗收：** 問她「為什麼刪掉 cell，變數還在？」她能答出「因為變數活在 Kernel 裡」就過關。

**Jupyter 三大坑小抄**（課後給她，見 `pandas-mental-model.md`）：

| 坑 | 症狀 | 解法 |
| :--- | :--- | :--- |
| 亂序執行 | 結果跟想的不一樣 | 從上往下重跑；懷疑時就 Restart & Run All |
| 變數殘留 | 刪掉的代碼還在影響結果 | Kernel → Restart，乾淨重來 |
| 執行狀態看不懂 | 不知道哪個跑了、哪個沒跑 | 看 cell 左邊：`[*]` 執行中、`[數字]` 跑完、空白＝沒跑過 |

### Phase 3：Pandas 六個動作（45–95 min）

**開場比喻（3 分鐘）：**

```text
「Pandas 只有一個核心概念：DataFrame 就是一張 Excel 表。

- 每一行＝一筆記錄
- 每一列＝一個欄位（也就是一個 Series）
- index＝每一行的行號貼紙

你對 Excel 會做什麼？篩選、選幾欄、加總、排序。
Pandas 的所有操作，就是這四件事：篩、選、算、排。
你不需要背 50 個函數，你只需要會講『我想對這張表做什麼』，
剩下的 Codex 幫你寫。」
```

**六個動作（每題固定節奏：她說中文需求 → Codex 生成 → 跑 → 驗算）：**

| # | 時間 | 中文需求（她親口說） | Codex 會生成的代碼 | 驗算點 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 45–52 | 「把 sample-sales.csv 讀進來」 | `pd.read_csv('data/sample-sales.csv')` | `df.shape` 是不是 (20, 5)？ |
| 2 | 52–60 | 「讓我看一眼數據長什麼樣」 | `df.head()` / `df.info()` / `df.describe()` | 欄位名對不對？有沒有缺失值？ |
| 3 | 60–66 | 「只給我看 profit 這一欄」 | `df['profit']` | 拿出來的是 Series（一欄），不是 DataFrame |
| 4 | 66–74 | 「只留利潤大於 20 的行」 | `df[df['profit'] > 20]` | 肉眼數有幾行，對得上嗎？ |
| 5 | 74–86 | 「算每個門店 5 年的利潤總和」 | `df.groupby('store')['profit'].sum()` | **手算驗算**：18+22+25+30+35=130，對答案 |
| 6 | 86–95 | 「畫各門店利潤總和的條形圖」 | `df.groupby('store')['profit'].sum().plot(kind='bar')` | 對照 Session 12 選圖模型：比較→條形圖 ✓ |

**第 5 題是全場最重要的一題，話術：**

```text
「停。Codex 跑出來的數字，先不要信。
拿出計算機（或心算）：門店A 5 年的利潤，18+22+25+30+35，是多少？
130。Codex 跑出來的是不是 130？
對上了——這個『對上了』的瞬間，就是你真正懂 groupby 的瞬間。
groupby 就是：按某一欄把表切成幾疊，每一疊各自加總。」
```

- [ ] 第 1–4 題可以快，重點是讓她習慣「說中文 → Codex 寫 → 我驗算」的節奏。
- [ ] 第 5 題放慢，手算驗算是不可跳過的儀式。
- [ ] 第 6 題連回 Session 12 的選圖模型（比較→條形圖），讓她看到兩堂課是連起來的。
- [ ] **驗收：** 遮住小抄，問她「篩、選、算、排各舉一個例子」，能說出來就過關。
