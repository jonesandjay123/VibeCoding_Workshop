# Session 13 導師手冊：先聽懂問題，再選一個例子

這份手冊幫你臨場判斷，不要求你按頁講完。Session 12 沒有實際上課，不預設學生已懂 Python、Pandas、選圖或工具設定。

## 先記住三件事

1. 先看她最近真正使用的資料與作業。不要一開場就叫她跑教材。
2. 每次只問一個問題、做一個動作。看完結果，再說原因。
3. 本次只處理一個主要問題。素材庫是用來補卡點，不是上課進度表。

## 00–20 分鐘：了解她現在在哪裡

可以這樣開場：

「妳最近用 Codex 做了什麼？先打開給我看看。今天不用把這份 notebook 全部跑完，我們先找一件妳最想弄懂或完成的事。」

依序問，上一題還沒回答完，不要一口氣補四個問題：

- 「這份作業要妳做什麼？」請她指題目，不急著看代碼。
- 「妳現在做到哪一步？」請她示範已經能完成的部分。
- 「接下來是哪裡卡住？」讓她指出一個具體畫面、數字或錯誤。
- 「今天結束前，妳最希望哪件事能變清楚？」

第 15–20 分鐘，整理成一句話讓她確認。例如：

「今天先弄清楚這張圖上的數字怎麼算出來。結束時，妳能挑一根柱子，從原始資料重新算一次。」

這只是例子，不要替她決定題目。若她不方便分享檔案，請她口述問題和欄位；用合成資料示範相同概念，不要求上傳原件。

## 共用的 120 分鐘時間框架

| 時段 | 用途 |
| :--- | :--- |
| 00–20 | 看實際作業、了解目標、選一個問題 |
| 20–30 | 確認最小環境，選支線 A、B 或 C |
| 30–55 | 一起做選定問題的第一步 |
| 55–60 | 休息 |
| 60–85 | 繼續同一個問題，核對結果 |
| 85–100 | 她自己操作一小步，或說明一個改動 |
| 100–105 | 機動時間；若前面已借用，就不再追加 |
| 105–115 | 保存並重跑本次選定的分析 |
| 115–120 | 回顧成果與仍需要的幫助 |

三條支線只是不同路線，總長都仍是 120 分鐘。超時時縮小題目或取消進階內容，保留休息與最後的核對。

## 20–30 分鐘：確認最小環境

先依今天選定的問題，只檢查會用到的環境。

如果走支線 A，先在目前的 Python kernel 執行 `print(1 + 1)`，看到 2 就可以開始 cell 與變數的實驗；這條支線不需要先安裝 pandas 或 matplotlib。

如果要用 Pandas 看表或分析，再執行 workbook 模組 0 的環境格，看它顯示的 Python 路徑。若只是口頭核對現有結果，也不用為了教材而先安裝新套件。

如果出現 `ModuleNotFoundError: No module named 'pandas'`，意思是**這個 kernel 使用的 Python 找不到 pandas**，不是資料壞了。先確認選了哪個 Python；新建 `.venv` 不會自動帶有分析套件。需要安裝時，請工具針對這個環境處理，完成後再跑環境格。

環境格成功只代表這一步成功，不能因此說整份 notebook 都測過了。AI 的「已安裝」也要用實際 import 結果確認。

環境排查最多額外借 5 分鐘機動時間。仍不通就用導師已確認可用的環境；課中先完成理解與驗證，學生端重跑留待補做。

## 支線 A：她不明白 cell 與 kernel 怎麼執行

**何時選這條：** 她問「為什麼上面改了，下面沒變？」或「為什麼重跑後數字不一樣？」

先用一句話說明：「每個代碼格會把指令交給同一個 Python 程序。這個程序叫 kernel，它記得剛才的變數。Notebook 不會因為你修改上面的格子，就自動從上到下重算。」

另開一份不含私人資料的 scratch notebook。不要在她原來的作業上做刪格實驗。

### 第一步：重跑「設定值」

在一個代碼格輸入：

```python
x = 10
print(x)
```

請她執行一次，再執行一次。兩次都應顯示 `10`。

原因：`x = 10` 每次都把 x 設成 10。它沒有在原來的值上增加什麼。

### 第二步：重跑「在原值上加一」

新增下一個代碼格：

```python
x = x + 1
print(x)
```

先問：「現在 x 是 10，這一格跑一次會變成多少？」執行後應顯示 `11`。只再跑這一格，應顯示 `12`。

原因：右邊先讀取目前的 x，再加 1，最後把結果存回 x。這一格依賴 kernel 裡目前的值。

### 第三步：看出畫面順序不等於自動更新

回去只跑第一格。它把 x 設回 `10`，但第二格下面先前顯示的 `12` 仍可能留在畫面上。

新增一格，只寫 `print(x)`，現在應顯示 `10`。舊輸出是一張先前結果的紀錄，不是會自動更新的儀表板。

如果這樣已經解答她的問題，就回到她的作業，不必再做下面延伸。

### 需要時才補：刪格與重啟

在上述步驟完成後，刪掉前兩個賦值格，保留 `print(x)`。只執行它，仍應顯示 `10`，因為刪除文件中的代碼不會清掉 kernel 的記憶。

接著**只重啟 kernel，不要全部執行**。再跑 `print(x)`，應出現 `NameError`，因為新的 kernel 還不知道 x 是什麼。

最後在 `print(x)` 上方補回 `x = 10`。重啟後依序全部執行，應顯示 `10`。這次不會報錯，因為前面的格子重新定義了 x。

**檢查理解：** 請她指出，自己的作業需要先跑哪一格、哪一個舊輸出應該重算。不要把整段實驗背出來當成驗收。

## 支線 B：她不清楚表格如何變成答案

**何時選這條：** 程式能跑，但她不明白 `shape`、篩選或加總的意思。

先問：「這份資料的一行代表什麼？」如果不能回答，先一起看原表；不要立即講 `groupby`。

依卡點選一段，不必全部講：

- **看表。** Workbook 模組 1：`shape` 告訴你整張表有 20 行、5 欄；`head()` 只預覽前 5 行，沒有刪掉後面的 15 行。
- **篩行。** 模組 4：從原本 20 行留下 `profit > 20` 的 9 行。畫面只列出店、年、利潤 3 欄，是另外做了「選欄」，不代表篩選會自動刪欄。
- **分組加總。** 模組 5：先單獨看 A 店的 5 行，再把 18、22、25、30、35 相加，得到 130。四家店都做同樣的事，20 行就變成 4 個總數。

一次只做目前需要的操作。`pd` 是 pandas 的簡稱、`df` 是變數名；她問到再解釋。Series、雙括號、dtype、assert 都有小抄可查，不需要先通過這些名詞才能繼續。

**檢查理解：** 請她用自己的資料或合成例子說明：「留下了哪些行？合併了哪些行？答案的單位是什麼？」只問與這次選題相關的一題。

## 支線 C：AI 做出了結果，但她不知道是否正確

**何時選這條：** 她已經有圖或表，卻不知道怎麼驗證。

先請她用一句話說題目要回答什麼，再看 AI 實際用了哪張表。

例子：題目要「2025 年各店利潤」，AI 卻對全部 20 行按店加總。圖能正常產生，但它回答的是「五年總和」。這叫問題和計算方式不一致，不是語法錯誤。

依序核對：

1. 先看年份：是不是只留下題目要的期間？
2. 再挑一個數字：它來自哪些原始行？用計算機或心算核對一次。
3. 最後看圖：標題和單位是否符合剛才那張結果表？

若缺少某個操作概念，才借用 workbook 裡相應的模組解釋。不要因為圖已經畫好了，就跳過中間表；也不要每次都叫 AI 整份重寫。

**檢查理解：** 她能指出至少一項具體證據，說明結果回答了問題。不是只說「AI 說它對」。

## 85–120 分鐘：完成一小步，誠實收尾

85–100 分鐘，請她自己做一個與目標相關的小動作。例如換成年份 2024、修正一個篩選條件，或指出應該先執行哪個 cell。先讓她說預期有什麼變化，再執行；不用為每行代碼做預測。

105–115 分鐘，保存本次選定的分析。若使用 workbook，只重跑本次用到的模組和列明的前置步驟；不要臨時把沒教過的內容全跑一遍。需要完整交付時，可另存一份精簡 notebook，保留必要代碼與說明，從乾淨 kernel 順序重跑。真實資料與成果保留在合適的私人位置。

有圖就打開新輸出的圖片，檢查標籤與數字；本次目標只有理解或得到一張表，就不強迫交 PNG。

最後 5 分鐘問：「今天哪件事比較清楚了？」再問「還有哪一步需要下次幫忙？」根據實際成果記錄獨立完成、提示後完成或待補，不用固定考卷評分。

## 語音協作：把當下情況說清楚

助手不會自動看到導師的 Zoom 或學生的畫面。導師可用以下方式請求即時幫助：

「她現在想知道＿＿。畫面上這格是＿＿，剛剛執行後顯示＿＿。她不懂的是＿＿。請先給我一句白話說法，再給一個可以問她的小問題。」

可以用手機語音協助，同時在電腦上進行 Zoom，但這不代表助手加入了 Zoom，也不代表能直接取得系統音訊。環境聲可能有回音或雜訊，導師轉述或截圖較可靠；視需要暫停或分段通話，不預設連續通話的時長。

只提供必要的代碼或已去識別的截圖。要傳真實作業或學生資料前，先確認她同意及分享範圍。語音協助以解釋當下卡點為主，不假定助手已看到畫面或知道最新執行狀態。

## 課中臨時修改與更新教材

1. 先說明要改哪一段、目前預期行為和希望改善什麼。一次只改一個小問題。
2. 導師先繼續教可進行的部分。修改、測試與推送需要時間；請等到明確的 commit／已推送確認。
3. 更新本機前先保存 notebook，確認本機所在分支及 `git status`。未保存的格子不一定會出現在 Git 狀態裡。
4. 若有本機修改，先保留副本並比較；需要時把新版下載到另一個資料夾。不要用 reset、force 或覆蓋方式丟掉課中內容，也不要盲目在未保存的 notebook 上 pull。
5. 確認本機工作區乾淨、分支正確後，才使用 `git pull --ff-only`。如果它失敗，停下來查看分歧，不強制更新。
6. 重新打開或重新載入新版前，先確認已保留本機內容；之後重跑必要的前置格。下載新版不會自動更新正在執行的 kernel。

本機新建的 `.venv` 或安裝的套件，不是教材內容變更，不加入 repo。也不因為要同步教材，就把私人作業和舊輸出一起提交。
