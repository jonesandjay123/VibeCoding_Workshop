## 一、學生心理狀態 & 注意事項

### 她是誰
- 大二東亞史，不是理工科 — **她用的是文科腦，比喻 > 邏輯推導**
- 想當 KOL、做品牌 — 動力是「這對我的夢想有用嗎？」不是「這技術很酷」
- 中日雙語 — 可以用中文或日文溝通，commit message 也鼓勵她用中文
- Session 1 已做出 azunyan.hp — 她有成功經驗，但可能還不確定自己「到底會不會」

### 心理狀態預測
| 時間點 | 可能的心理狀態 | 你該做的 |
|--------|---------------|---------|
| 開場 | 有點緊張（上次隔了一段時間） | 先看她的網站，誇具體的東西暖場 |
| 打開 Terminal | 害怕（黑色視窗 = 駭客？） | 「就是跟電腦傳 LINE」，語氣輕鬆 |
| 第一次 clone 成功 | 驚喜 + 鬆一口氣 | 讓她享受這個 moment，別急著往下 |
| 第一次 push 成功 | 今天最高潮！超興奮 | 🎉 用力誇！這是今天的核心記憶 |
| Block 4 (JS/API) | 腦袋已經累了 | 刻意放輕鬆，狗圖 API 讓她笑一下 |
| 第二次獨立 git 循環 | 「欸我好像真的會了」| 少說話，讓她自己來，成功後才誇 |
| Demo 環節 | 好奇 + 「這也太神了」| 讓她感受到可能性，不用解釋技術 |

### 🚨 節奏控制原則
1. **每 25-30 分鐘一個小成就**（見課程大綱的成就感曲線）
2. **Block 4 的休息不能跳過** — 前 90 分鐘她的腦已經超載
3. **如果她某個步驟卡住超過 2 分鐘** — 給提示，不要讓她挫折太久
4. **如果她明顯疲倦** — 提前進入 Block 6 的 demo，輕鬆收尾
5. **讓她自己打指令** — 你的手不碰她的鍵盤，除非認證環節真的卡住

## 二、每個環節的「如果卡住」備案

### Block 1：回顧 + 世界觀
| 卡住情況 | 備案 |
|---------|------|
| 她說「上次的都忘了」| 「沒關係！我們一起看你的網站，看著看著就想起來了」，打開她的 GitHub Pages |
| 世界觀比喻聽不懂 | 換成 IG 比喻：「你的 IG 個人頁 = 靜態前端，IG Feed = 動態後端」|
| 她問「那我現在到底會什麼」| 指著圖：「你已經在前端 70% 的位置了！」— 這句話很重要 |

### Block 2：Terminal + Clone
| 卡住情況 | 備案 |
|---------|------|
| Terminal 打不開 | Spotlight (Cmd+Space) → 搜尋 "Terminal" |
| git 沒安裝 | 會跳出安裝 Xcode Command Line Tools 提示 → 按 Install，等 5 分鐘 |
| clone 需要認證 | **提前準備好！** SSH key 或 Personal Access Token，見腳本附錄 A |
| 她打錯字 | 「沒關係，按上鍵可以叫回上一個指令，改一下再按 Enter」|
| Terminal 顯示亂碼 | 可能是中文資料夾名稱問題 → 先 `cd ~/Desktop` 確保在英文路徑 |

### Block 3：add / commit / push
| 卡住情況 | 備案 |
|---------|------|
| 不知道改什麼 | 「改 title 加個 emoji 就好！最簡單的改動」|
| commit message 不知道寫什麼 | 「寫什麼都可以，中文 OK，就寫你做了什麼：'改了標題顏色'」|
| push 被 rejected | 可能要先 `git pull --rebase` → 再 `git push` |
| push 要帳密 | 用 Personal Access Token 當密碼（提前準備！）|
| 忘了加 `-m` 跳進 vim | 按 `Esc` → 打 `:q!` → Enter → 重新打 `git commit -m "訊息"` |

### Block 4：JS 概念 + API
| 卡住情況 | 備案 |
|---------|------|
| JS 公式聽不懂 | 直接用她網站舉例：「如果按鈕被點，頁面變深色 — 就這樣」|
| Dog API 打不開 | 備用：`https://api.dicebear.com/6.x/pixel-art/svg?seed=azunyan`（生成她的頭像）|
| 她問「API 很難學嗎」| 「你剛剛不就用了嗎？貼個網址就是呼叫 API。以後用 AI 工具的話更簡單」|

### Block 5：第二次 Git 循環
| 卡住情況 | 備案 |
|---------|------|
| 忘記指令順序 | 給她看速查卡，讓她自己找答案（不要直接告訴她）|
| git log 畫面出不來 | 按 `q` 退出。如果她好奇，帶她看 GitHub 網頁版的 commit history |

### Block 6：Demo + 收尾
| 卡住情況 | 備案 |
|---------|------|
| NotebookLM 加載太慢 | 提前上傳好 PDF，課堂直接開已有的 Notebook |
| Audio Overview 生成太久 | 先展示文字問答功能，Podcast 可以課後聽 |
| 她看起來太累了 | 跳過 OpenClaw demo，直接到路線圖 + 作業，溫馨收尾 |

## 三、不要說的話 / 要說的關鍵句

### 🚫 絕對不要說
| ❌ 不要說 | 為什麼 |
|----------|--------|
| 「這很簡單」 | 對她來說不簡單。她會覺得「簡單我還搞不懂 = 我很笨」 |
| 「你應該知道的吧」 | 她不知道，而且會不好意思問 |
| 「這個你以後就懂了」 | 太敷衍，她會覺得你在糊弄 |
| 「branch」「merge」「conflict」 | 太早了，只會嚇到她 |
| 「HEAD」「detached HEAD」 | 完全不需要，Git 術語地獄 |
| 「你錯了」「不是這樣」 | 改成「差一點點！把這裡改成…」 |
| 「很多人都會」 | 她不是很多人，她是她 |
| 「這是基礎中的基礎」 | 暗示她連基礎都不會 |

### ✅ 要說的關鍵句（每句都有設計意圖）

#### 建立信心
- 「你上次從零做出一個網站，而且全世界都看得到。」（提醒她已有的成就）
- 「你已經站在前端 70% 的位置了。」（量化進步，製造驚喜）
- 「今天只學六個指令。真的只有六個。」（降低心理門檻）

#### 去魔化技術
- 「Terminal 就是跟電腦用文字聊天。」（把可怕的東西變親切）
- 「Git 就是幫你的程式碼存檔。」（一句話解釋完）
- 「你不用自己寫 JS，但要能看懂菜單。」（設定合理期望）

#### 強化成就感
- 「你剛剛用一行指令，把整個網站從 GitHub 下載到電腦了。」（clone 成功後）
- 「🎉 你用三行指令，把改動推上了全世界看得到的網站！」（push 成功後 — **今天最重要的一句**）
- 「你剛剛完全靠自己做到了。」（第二次 git 循環後）

#### 連結到她的目標
- 「你的中日雙語和品牌想法才是核心競爭力。技術是放大器。」（Demo 環節）
- 「你已經不是只會做漂亮海報的人了，你是一個會用專業工具的品牌創作者。」（結尾 — **全課最後一句**）

## 四、學生可能的提問 + 建議回答

### Git 相關
| 可能的問題 | 建議回答 |
|-----------|---------|
| 「clone 跟 download ZIP 有什麼不同？」 | 「ZIP 是照片，clone 是整個遊戲存檔歷史。clone 以後可以繼續存新進度、同步雲端。」 |
| 「為什麼要先 add 再 commit？為什麼不能直接存？」 | 「因為有時候你改了 5 個檔案但只想存 3 個。add 就像在 IG 選圖，commit 才是發布。」 |
| 「commit message 寫中文可以嗎？」 | 「完全可以！用你最自然的語言。工程師界沒有規定要寫英文。」 |
| 「git pull 什麼時候用？」 | 「在別台電腦改東西之後，或有人幫你改了。下次教。」 |
| 「那 branch 是什麼？」 | 「你可以想成遊戲的平行世界——試試新玩法但不影響主線。這個下次教，今天先搞定主線！」 |
| 「push 會覆蓋掉 GitHub 上的東西嗎？」 | 「不會！它是把新存檔加上去。之前的存檔都還在。」 |
| 「如果 push 失敗了怎麼辦？」 | 「通常是身份驗證問題，我來幫你看。」（→ 用提前準備好的 Token/SSH） |

### 概念相關
| 可能的問題 | 建議回答 |
|-----------|---------|
| 「前端和後端到底差在哪？」 | 「前端 = 你看得到摸得到的，後端 = 幕後處理。就像店面 vs 廚房。」 |
| 「API 很難學嗎？」 | 「你剛剛不就用了嗎？在瀏覽器貼個網址就是呼叫 API 了。」 |
| 「我真的需要學 JavaScript 嗎？」 | 「不急。你先理解概念就好。以後真的要加功能，可以叫 AI 幫你寫。但你要能看懂它寫的對不對。」 |
| 「Vibe Coding 是什麼？」 | 「用說話的方式告訴 AI 你要什麼，AI 幫你寫程式碼。你不用會寫，但要能看懂。」 |

### 品牌 / 生涯相關
| 可能的問題 | 建議回答 |
|-----------|---------|
| 「這些東西對我當 KOL 有什麼用？」 | 「會 coding 的 KOL 可以自己架站、分析數據、做 AB 測試、自動化發文。不會的只能依賴平台。你有一個別人沒有的優勢。」 |
| 「我不是工程師，學這些會不會浪費時間？」 | 「你不需要成為工程師。但會一點 coding 的 KOL 和不會的，差距是巨大的。（舉 Maya Bello 的例子）」 |
| 「有沒有像我這樣背景的人成功的例子？」 | 「Lydia Hallie，荷蘭女生，15 歲自學 HTML/CSS，沒有 CS 學位，現在是頂級技術 KOL。Tom Shaw 2020 年才開始學 coding，邊學邊記錄就變成了 content creator。」 |
| 「我的雙語背景有用嗎？」 | 「超有用。在日中國人 KOL 網絡有 200+ 創作者、1 億粉絲。你的雙語能力是 VIP 門票。」 |

## 五、課後 Follow-up 建議

### 📱 課後 24 小時內
- [ ] **傳一則訊息**：「今天辛苦了！你做得超好 🎉 記得自己試一次 git push 喔」
- [ ] **傳速查卡** P3 的 PDF/圖片版，讓她存在手機裡
- [ ] **傳資源清單** P4，但跟她說「不用全部看，挑一個有興趣的就好」

### 📅 3-5 天後
- [ ] **確認作業**：「有自己 push 成功嗎？有任何問題隨時問我」
- [ ] **如果她沒做**：不要催，改問「最近忙嗎？下次上課前再做也行」
- [ ] **如果她做了**：「太厲害了！你的 commit 紀錄越來越多了 ✨」

### 📅 下次上課前
- [ ] 確認她的 Git 環境還能正常運作（token 沒過期等）
- [ ] 看她的 GitHub repo 有沒有新的 commit（了解她課後有沒有練習）
- [ ] 準備 Session 3 的內容（JavaScript 基礎 or Vibe Coding 入門）

### 🎯 Session 3 建議方向（擇一）
1. **JavaScript 基礎**：用她的網站加一個深色模式按鈕（實作「當/對/做」公式）
2. **Vibe Coding 實作**：用 Cursor 或 Replit + AI 做一個小功能
3. **品牌站升級**：用 Framer AI 生成新頁面，結合她已有的 HTML/CSS 技能

> 根據她課後的反應來決定。如果她很興奮想動手 → 選 1 或 2。如果她更想做品牌 → 選 3。
