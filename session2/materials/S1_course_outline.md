## Block 2 ▸ 主菜①：Git 概念 + Terminal 初體驗 + Clone
**⏰ 0:30 – 1:00 ｜ 能量：升高中**

### 🎯 目標
- 用電玩存檔比喻理解 Git
- 第一次打開 Terminal
- 成功 clone 自己的 repo

### 📋 具體步驟

#### Part A — 電玩存檔比喻（0:30 – 0:38）
1. 問她：「你有打過 RPG 遊戲嗎？或是任何有存檔功能的遊戲？」
2. 不管有沒有，用這個比喻：

> 💬 **關鍵句：**「你知道打遊戲的時候，打 Boss 前會先存檔嗎？Git 就是幫你的程式碼做這件事。每次存檔就叫一個 commit，萬一搞砸了可以回到之前的存檔點。」

3. 快速帶過六個核心指令（**只是預覽，不用記**）：

| 指令 | 遊戲比喻 | 一句話 |
|------|---------|--------|
| `git clone` | 下載遊戲 | 把 GitHub 上的專案抓到電腦 |
| `git status` | 看看現在的狀態 | 「我改了什麼？」 |
| `git add .` | 選擇要存的進度 | 「我要存這些東西」 |
| `git commit -m "訊息"` | 按存檔鍵 | 正式記錄，附一句備忘 |
| `git push` | 上傳雲端存檔 | 同步到 GitHub |
| `git pull` | 下載雲端存檔 | 從 GitHub 拿最新版 |

> 💬 **關鍵句：**「今天只學這六個。真的只有六個。工程師每天用的也就是這些。」

#### Part B — Terminal 初體驗（0:38 – 0:48）
4. 打開 Terminal.app（Spotlight 搜尋 "Terminal"）
5. **讓她自己打開**，不要幫她操作
6. 看到黑色視窗後：

> 💬 **關鍵句：**「這個黑色視窗叫 Terminal，你可以把它想成——跟電腦用文字聊天。平常你用滑鼠點來點去，現在你改用打字跟它說話。」

7. 教三個基本指令（讓她一個一個打）：
   ```
   pwd          → 「你現在在哪裡？」（print working directory）
   ls           → 「這裡有什麼東西？」（list）
   cd Desktop   → 「走到桌面去」（change directory）
   ```

8. 每打一個，停下來確認她看到的畫面：
   - `pwd` → 應該顯示 `/Users/她的名字`
   - `ls` → 會看到 Desktop, Documents 等資料夾
   - `cd Desktop` → 再打 `pwd` 確認位置變了

> 💬 **關鍵句：**「你剛剛做的事情，就是用文字在電腦裡走路。`pwd` 是問路，`ls` 是看周圍，`cd` 是走過去。」

#### Part C — Clone！（0:48 – 1:00）
9. 確保她在 Desktop 目錄：`cd ~/Desktop`
10. 打開 GitHub，進到她的 azunyan.hp repo
11. 點 Code 按鈕 → 複製 HTTPS URL
12. 回到 Terminal，**她自己打**：
    ```
    git clone https://github.com/azunyanchannel/azunyan.hp.git
    ```
13. 看到下載訊息！
14. 然後：
    ```
    cd azunyan.hp
    ls
    ```
15. 她會看到自己的 HTML/CSS 檔案出現在 Terminal 裡！

> 💬 **關鍵句：**「你剛剛用一行指令，把你的整個網站從 GitHub 下載到電腦了。以前要手動下載，現在一行字搞定。」

### 🎭 預期學生反應
- 打開 Terminal 時可能有點害怕（黑色視窗 = 駭客？）→ 用「跟電腦聊天」化解
- `ls` 看到自己的資料夾會有親切感
- `git clone` 成功後看到自己的檔案 → 「哦哦哦！我的東西！」

### ✅ 成就感 Moment
> 「我用 Terminal 把自己的網站 clone 下來了！」

## Block 3 ▸ 主菜②：Git 核心循環 — add / commit / push
**⏰ 1:00 – 1:30 ｜ 能量：高峰 🔥**

### 🎯 目標
- 完成完整的 git add → commit → push 循環
- 在 GitHub 上看到她的改動
- 理解「改→存→上傳」的節奏

### 📋 具體步驟

#### Part A — 做一個小改動（1:00 – 1:08）
1. 在 Terminal 裡確認位置：`pwd` → 應該在 azunyan.hp 資料夾
2. 用 Finder 打開這個資料夾（或用 `open .`）
3. 用她習慣的編輯器打開 `index.html`
4. **讓她自己選要改什麼**，建議：
   - 改一行標題文字（例：加上今天的日期或一句話）
   - 或改 CSS 裡某個顏色
5. 存檔

> 💬 **關鍵句：**「你改什麼都可以，隨便改一個小東西就好。這是你的網站，你想怎麼改就怎麼改。」

#### Part B — git status（1:08 – 1:12）
6. 回到 Terminal：
   ```
   git status
   ```
7. 會看到紅色的檔案名稱 → 代表「有東西改了但還沒存檔」
8. 解釋：

> 💬 **關鍵句：**「紅色 = Git 跟你說『欸，我發現你改了這些東西，你要存檔嗎？』它很聰明，會自動知道你改了什麼。」

#### Part C — git add + git commit（1:12 – 1:20）
9. 打指令（讓她打）：
   ```
   git add .
   ```
10. 再看一次：
    ```
    git status
    ```
11. 檔案變**綠色**了！

> 💬 **關鍵句：**「綠色 = 你已經選好要存的東西了，就像打遊戲的時候選好要存哪個進度。」

12. 現在正式存檔：
    ```
    git commit -m "改了首頁標題"
    ```
    - commit message **讓她自己寫**，用中文完全OK
    - 鼓勵她寫她能理解的內容

> 💬 **關鍵句：**「`-m` 後面的字是給未來的自己看的備忘錄。一個月後你回來看，就知道那天改了什麼。」

#### Part D — git push！（1:20 – 1:28）
13. 最關鍵的時刻：
    ```
    git push
    ```
    - ⚠️ 可能會跳出要求登入 → 用 GitHub Token 或 credential helper
    - **提前準備好認證方式**，不要讓她在這裡卡住
14. Push 成功！
15. **立刻打開 GitHub 網頁**，重新整理她的 repo
16. 讓她看到：改動已經出現在 GitHub 上！
17. 如果有 GitHub Pages，打開網站看看改動

> 💬 **關鍵句：**「🎉 你剛剛用三行指令，把你的改動推上了全世界都看得到的網站。上次要手動上傳，現在三行字搞定。這就是工程師每天在做的事。」

#### Part E — 快速回顧循環（1:28 – 1:30）
18. 在紙上或螢幕上畫：
    ```
    改東西 → git add . → git commit -m "備忘" → git push → 完成！
         （選好）    （存檔）           （上傳）
    ```

> 💬 **關鍵句：**「記住這個節奏：改、選、存、傳。四步。你已經會了。」

### 🎭 預期學生反應
- `git status` 看到紅/綠色變化 → 有趣（「它會自己知道！」）
- 寫 commit message 時可能猶豫 → 強調「寫什麼都可以」
- **push 成功後在 GitHub 看到自己的改動** → 這是今天最大的高潮！會超興奮
- 可能會說「這比手動上傳方便多了吧！」→ 「沒錯！」

### ✅ 成就感 Moment
> 「我用 Git push 了！GitHub 上看到我的改動了！！」🎉（今天的最高潮）

## Block 4 ▸ 配菜：休息 + JavaScript 概念 + API 概念
**⏰ 1:30 – 2:00 ｜ 能量：低 → 慢慢回升（刻意設計的放鬆區）**

### 🎯 目標
- 休息恢復精力
- 用比喻理解 JS 的角色（不寫程式碼）
- 用比喻 + 瀏覽器體驗理解 API
- 輕鬆愉快，無壓力

### 📋 具體步驟

#### Part A — 休息（1:30 – 1:35）☕
- 站起來走走、喝水、上洗手間
- **不要跳過這個！她的腦已經超載了。**

> 💬 **關鍵句：**「你剛剛學了一個工程師級的技能，休息一下是應該的。」

#### Part B — JavaScript 概念（1:35 – 1:45）
> ⚠️ **這段只教概念，完全不碰程式碼！**

1. 回到剛才的品牌開店比喻圖，指著 JavaScript 那行：

> 💬 **關鍵句：**「你已經有了漂亮的店面裝潢（HTML + CSS）。JavaScript 就是讓店面『有反應』的東西——客人按門鈴會響、開關按了燈會亮、滑到哪東西會動。」

2. 用她的網站舉例（不用寫 code，只是「如果...就可以...」）：
   - 「如果你加 JS，首頁可以有一個深色模式切換按鈕 🌙」
   - 「About 頁面的技能標籤可以點了展開」
   - 「SNS 頁面可以有一個『複製連結』按鈕」

3. 引出「讀 code 比寫 code 重要」的概念：

> 💬 **關鍵句：**「JS 你現在不需要自己從零寫。以後可以叫 AI 幫你寫，但你要能看得懂它在做什麼。就像你不用自己做菜，但要能看懂菜單。」

4. 教她黃金公式（寫在紙上）：
   ```
   「當 ___（什麼事發生），對 ___（哪個東西），做 ___（什麼反應）」
   ```
   - 例：「當按鈕被點擊，對整個頁面，加上深色模式」
   - 例：「當滑鼠移到圖片上，對圖片，放大一點」

> 💬 **關鍵句：**「所有 JavaScript 都可以用這個公式理解。以後看到任何 code，你就問自己這三個問題。」

#### Part C — API 概念 + 瀏覽器體驗（1:45 – 2:00）

5. UberEats 比喻：

> 💬 **關鍵句：**「你用 UberEats 的時候，需要知道餐廳的廚房長什麼樣嗎？不需要。你只要在 APP 點餐，食物就來了。API 就是這個——讓你的程式跟別的程式點餐的方法。」

6. **瀏覽器實作！**（這是配菜的動手環節）
   - 打開 Chrome
   - 在網址列貼上：
     ```
     https://dog.ceo/api/breeds/image/random
     ```
   - 按 Enter → 看到一個 JSON 回應，裡面有一個狗圖 URL
   - 把圖片 URL 貼到新分頁 → 看到一張隨機狗圖！

> 💬 **關鍵句：**「恭喜，你剛剛呼叫了一個 API！你跟一台電腦說『給我一張狗圖』，它就給你了。你的天氣 APP、IG、Uber 每天都在做一樣的事。」

7. 再試一個更有趣的：
   - 貼上：`https://api.dicebear.com/6.x/pixel-art/svg?seed=azunyan`
   - 看到一個用她名字生成的像素大頭貼！
   - 改 `seed=` 後面的字，每次都不同

> 💬 **關鍵句：**「你改了網址裡的參數，API 就給你不同結果。這就是所有 APP 背後的運作方式。你以後做品牌，可以串 Instagram API 在官網自動顯示最新貼文、串翻譯 API 讓日本粉絲看日文版。」

8. 連結到剛才的世界觀圖：
   - 前端（你的網站）→ 透過 API（服務生）→ 跟後端（廚房）要資料 → 資料庫（倉庫）裡拿出來

### 🎭 預期學生反應
- 休息後精神會好很多
- JS 公式「當/對/做」很容易記住
- **在瀏覽器貼 URL 看到狗圖** → 「好可愛！」→ 「等等這就是 API？」
- DiceBear 用她名字生成頭像 → 「好酷！可以用在我的品牌嗎？」
- 這段應該是最輕鬆有趣的一段

### ✅ 成就感 Moment
> 「我呼叫了一個 API！而且用我的名字生成了大頭貼！」

## Block 5 ▸ 主菜③：Git 第二輪練習 + 歷史紀錄
**⏰ 2:00 – 2:30 ｜ 能量：回升 → 穩定**

### 🎯 目標
- 獨立完成第二次 add → commit → push 循環
- 學會用 git log 看歷史
- 鞏固肌肉記憶

### 📋 具體步驟

#### Part A — 第二次改動（2:00 – 2:08）
1. 讓她自己選改什麼（例：改 CSS 顏色、加一段文字、改 About 頁面）
2. **這次 Jones 少說話，讓她自己嘗試**
3. 存檔

> 💬 **關鍵句：**「這次你自己來。改什麼都好，然後試試看記不記得那四步——改、選、存、傳。」

#### Part B — 獨立完成 Git 循環（2:08 – 2:18）
4. 她自己打（Jones 在旁邊看，只在她卡住時才提示）：
   ```
   git status       ← 看到紅色
   git add .        ← 選好
   git status       ← 看到綠色
   git commit -m "她自己寫的訊息"
   git push         ← 上傳！
   ```
5. 再次在 GitHub 確認改動出現

> 💬 **（只在她成功後說）：**「你剛剛完全靠自己做到了。第二次了。以後你改網站就是這個節奏，不用再手動上傳了。」

#### Part C — git log：看到自己的歷史（2:18 – 2:25）
6. 打指令：
   ```
   git log --oneline
   ```
7. 她會看到自己的所有 commit 紀錄！包括今天的兩個

> 💬 **關鍵句：**「這就是你的存檔紀錄。每一行都是你的一個存檔點。以後你的網站改了一百次，都能回來看自己什麼時候改了什麼。就像遊戲的存檔畫面。」

8. 也可以去 GitHub 網頁上看 commit history，視覺化更直覺

#### Part D — 小速查卡（2:25 – 2:30）
9. 給她一張（或螢幕上顯示）速查卡：

```
┌─────────────────────────────────────────┐
│  🎮 Git 六大指令速查                      │
│                                          │
│  git clone <URL>    → 下載專案            │
│  git status         → 看看改了什麼        │
│  git add .          → 選好要存的          │
│  git commit -m "…"  → 存檔 + 備忘        │
│  git push           → 上傳到 GitHub       │
│  git pull           → 下載最新版          │
│                                          │
│  日常節奏：改 → status → add → commit → push │
└─────────────────────────────────────────┘
```

> 💬 **關鍵句：**「這張卡你存著。下次自己改網站的時候照這個走就好。不用背，多打幾次就會記住了。」

### 🎭 預期學生反應
- 第二次做會順很多，可能不用看提示就記得順序
- `git log` 看到歷史紀錄 → 「哦！這就是存檔畫面！」
- 拿到速查卡會有安全感
- 可能會問「那 git pull 什麼時候用？」→ 「在別台電腦改東西的時候，或是有人幫你改了之後。下次教。」

### ✅ 成就感 Moment
> 「我自己獨立完成了一次 git 循環！而且看到了我的 commit 歷史！」

## 📝 教學備忘

### 課前準備清單
- [ ] 確認她的 Mac 有安裝 Git（`git --version`，Mac 通常內建）
- [ ] 準備好 GitHub 認證方式（Personal Access Token 或 SSH Key）
- [ ] 測試 `git clone` 她的 repo 是否正常
- [ ] 準備一篇東亞史 PDF 用於 NotebookLM demo
- [ ] 測試 Dog API 和 DiceBear URL 是否正常
- [ ] 準備速查卡（列印或數位版）
- [ ] 確認 NotebookLM 可以正常使用

### ⚠️ 絕對不要做的事
- ❌ 不要教 branch 和 merge（太早）
- ❌ 不要教 merge conflict（她會怕）
- ❌ 不要解釋 HEAD、detached HEAD 等術語
- ❌ 不要讓她寫任何 JavaScript（這次只教概念）
- ❌ 不要在認證環節卡太久（提前設好 credential）
- ❌ 不要用 VS Code 的 Git 按鈕（她要學 CLI）
- ❌ 不要說「很簡單」（對她來說不簡單）

### ✅ 要一直做的事
- ✅ 讓她自己打指令（Jones 不搶鍵盤）
- ✅ 每個步驟讓她先試，卡住了再幫
- ✅ 用中文或日文溝通都 OK
- ✅ 用她的名字和她的網站做範例
- ✅ 每個 block 結束時口頭確認「到這裡 OK 嗎？」
- ✅ 多用比喻、少用術語
- ✅ 鼓勵她用中文寫 commit message

### 備用方案（如果某個環節卡住）
| 問題 | 應對 |
|------|------|
| Terminal 打不開 | 用 Spotlight (Cmd+Space) 搜尋 "Terminal" |
| git 沒安裝 | 跳出安裝 Xcode Command Line Tools 的提示，按 Install |
| clone 要輸入帳密 | 用 GitHub Personal Access Token 作為密碼 |
| push 被拒絕 | 可能要先 `git pull`，帶她走一遍 |
| 她太累了 | 提前進入 Block 6 的 demo 環節，輕鬆收尾 |
| 進度超前 | 讓她多做一次 git 循環，或探索 `git diff` |
