## 為什麼是這個題目

Azunyan 在 9/24 早上傳來廈大《數據可視化》第四章簡報（70 頁，NumPy / Pandas / Matplotlib / Seaborn）。這門課有大數據時代的基因，但現在是開給非技術專業的應用課——它的真正目標不是背 API，而是「拿到一份數據，能清洗、能畫圖、能講出故事」。

學校的教法是參數表導向的，對非資工背景的學生非常不友好。Vibe Coding 的打法正好互補：

- **學校教「API 怎麼寫」→ 我們教「需求怎麼講、結果怎麼驗」。**
- **學校給 orders.txt 練習題 → 我們直接拿這三道題當場做完**，明天她交作業就能用上。
- **學校假設工具都可用 → 我們先解決她在廈門的真實工具困境**（Antigravity 的 AI Agent 即使用跳板也連不上）。

### 導師的誠實定位

導師不是 Data Scientist，不教統計理論、不裝懂。這堂課導師的專長是工程判斷與 AI 協作方法論：**怎麼把需求講到 AI 能一次做對、怎麼驗算 AI 的輸出、怎麼迭代**。這正是學生最缺、學校不教的部分。

## 本堂核心心智模型

```text
學生（需求方）                    AI Agent（執行方）
--------------------------        --------------------------
用中文描述「我想知道什麼」  →
                                  生成 pandas / matplotlib 代碼
                                ← 在 Jupyter 跑起來，產出表格與圖
檢查：數字對不對？圖合理嗎？
  → 不對 / 不好看 → 追問、要求重做 → 迭代
  → 對了 → 導出 png/pdf，收工
```

### 三種角色的分工

| 角色 | 負責 | 不負責 |
| :--- | :--- | :--- |
| **學生** | 講清楚需求、驗算結果、判斷圖表是否合理 | 背 API 參數、手寫 pandas 代碼 |
| **AI Agent** | 寫代碼、查文檔、修 bug | 保證結果正確（它會算錯、會選錯圖） |
| **導師** | 示範提問與驗算的方法、守住時間與工具鏈 | 講統計理論、代寫作業 |

### 關鍵觀念：探索 vs 溝通

這是整門《數據可視化》課的靈魂，簡報沒有講透：

- **探索式可視化（自己看懂數據）：** Matplotlib / Seaborn，分析師自己用的草稿。
- **溝通式可視化（給別人看懂）：** 標題、顏色、標註都要為讀者服務，交作業、做報告用的是這種。

今天做的三道題，前兩道是探索，第三道導出成圖時就要切換成溝通視角。

## 今天的關鍵決策與技術邊界

### 1. 為什麼不用 Antigravity？
學生在廈門實測：即使使用跳板（VPN），Antigravity 的 AI Agent 依然連不上。這是 Google 服務的區域限制，光換 IP 過不了帳號區域檢查。今天直接採用中國原生工具鏈（Trae 國內版 / 通義靈碼＋國內模型），**課堂上不再花任何時間除錯 Antigravity**。

### 2. 為什麼不教 Python 基礎語法？
學生不需要在這堂課學 `for` 迴圈或型別。Jupyter 只當「執行 Agent 代碼的地方」用。今天的認知預算全部留給：需求表達、驗算、選圖判斷。

### 3. 為什麼不講統計理論？
導師不是 Data Scientist，不裝懂。`mean / std / percentile` 這些函數用到時由 Agent 解釋，導師只確保學生理解「這個數字在回答什麼問題」。

### 4. 數據集用老師的，不用自造的
`orders.txt` / `customers.txt` 是課堂指定的數據集，直接用它們做，做出來的圖表明天就能交作業，成就感與實用性一次滿足。

## 今天明確不做（Non-Goals）

- 不講 NumPy / Pandas / Matplotlib 的 API 參數表（那是簡報的工作）。
- 不教 Python 基礎語法（型別、迴圈、Hello World）。
- 不講統計學理論（分佈、假設檢定等）。
- 不除錯 Antigravity、不糾結翻牆方案。
- 不一次裝多個 IDE；一個 primary 能跑就好。
- 不碰 Seaborn 進階（除非時間有剩，當彩蛋）。
- 不代寫作業：每一題的需求描述必須由學生親口說出，導師只示範第一題。
