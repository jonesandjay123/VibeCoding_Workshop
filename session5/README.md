## 內容概覽

Session 5 不是「再加更多功能」，而是教她一件更核心的事：

> **不是所有想法都一樣難。把想法整理好，再選一個真正做得到的去實作。**

我們用一個叫 **Idea Sorting Board** 的小工具，陪她把腦袋裡的點子倒出來、排一排、選一個、然後真的做出來。

### 核心學習流程

```
💡 想法 (Idea)
   ↓
🗂️ 分類 (Sort)
   ↓
🎯 選擇 (Choose)
   ↓
🛠️ 實作 (Build)
```

## 🎯 學習目標

這堂課結束時，她應該能夠：

- ✅ 理解**不是所有想法都一樣難做**（建立難度尺度感）
- ✅ 會把一個大想法**拆成小小的可執行功能**
- ✅ 能用 AI（Antigravity / LLM）**把自己選的功能做出來**
- ✅ 透過「自己選 + 自己完成」一個功能，**建立成就感與信心**
- ✅ 對「外部 API」有初步概念（知道 app 可以跟別的服務對話，但不需要懂技術細節）

---

## 🧠 為什麼這樣教？（教學哲學）

傳統的 coding-first 教學會直接教她寫更多 code、修更多 bug。但對零基礎學習者來說，真正卡住的往往不是「寫不出來」，而是：

- **想法太大**：想做「比 Google Calendar 更好的東西」，卻不知從何開始
- **沒有尺度感**：不知道哪些功能 30 分鐘能做完，哪些要三個月
- **容易挫折**：選了太難的題目，做到一半卡住就放棄

**Idea Sorting Board 的關鍵，是把「判斷力」這件事外顯化。**

當她親手把卡片從「想做」拖到「太難」、從「簡單」拖到「中等」的那個瞬間，她學到的不只是一個功能怎麼做，而是**未來她自己一個人的時候，要怎麼決定該做什麼**。

> 她現在不是缺夢想，而是缺「把夢想切小」的能力。
> 這堂課就是教她這個。

## 🎬 第一幕：暖身與複習（25–30 min）

**目標**：喚回前四堂的記憶，建立「我其實會不少東西」的信心。

### 活動流程

1. 打開 `cheatsheet.md`
2. **不要你講，讓她講** — 輕鬆的 Q&A：
   - 「`git status` 是做什麼的？」
   - 「`npm run dev` 跟 `npm run build` 差在哪？」
   - 「要把新改動存成一個版本，要打哪幾個指令？」
3. 她答對就給 ✅，答不出來再一起看 cheatsheet

### 💡 Teaching Tips

- **她講，你聽**。你只是提問者，不是講師
- 答錯完全沒關係，語氣輕鬆一點：「這個我們一起翻一下」
- 不要考太細節（例：`-rf` 是什麼不重要）
- 目標是 **recall + 放鬆心情**，不是小考

---

## 🎬 第二幕：Idea Sorting Board 活動（45 min）⭐ 核心

**目標**：教她**把想法具象化、排序、並做出決定**。

> ⚠️ 這是整堂課最重要的 45 分鐘。不要趕，讓她慢慢想、慢慢排。

### Step 1 — 產生想法（10 min）

問她：
> 「如果你的 DailyPlanner 可以多任何一個功能，你想要什麼？不用管做不做得到，先講出來。」

- 目標：至少 **8–12 個想法**
- 你幫她把每個想法寫成一張卡片（或用 Idea Sorting Board 工具輸入）
- 不做任何評價、不說「那個太難」

### Step 2 — 第一次分類：想做 / 不想做（5 min）

把所有卡片分成兩堆：
- 🟢 **想做的**（留下）
- ⚪ **其實沒那麼想要**（移走）

### Step 3 — 第二次分類：難度（20 min）⭐ 最關鍵

把「想做的」這堆，再拖到三個欄位：

| 欄位 | 她的直覺 | 大概意思 |
|---|---|---|
| 🟢 **簡單** | 「這個應該很快吧」 | 改字、改顏色、加一個欄位 |
| 🟡 **中等** | 「好像要想一下」 | 新的互動、存到 localStorage |
| 🔴 **困難** | 「感覺好難喔」 | 串 API、登入、多人協作 |

**重點來了**：讓她**自己拖**，你只問問題、不要替她決定。

她拖完之後，一起討論：
- 「你為什麼覺得這個是難的？」
- 「如果我們把這個功能只做一半，會變成簡單的嗎？」
- 「這個真的難，還是只是聽起來難？」

### Step 4 — 觀察：同一個想法，換個角度就不同（5 min）

挑一張她歸為「困難」的卡片，示範：

> 「你看『做一個 Google Calendar 整合』是很難。但如果只是『在頁面上顯示我今天的 3 個行程』呢？」

讓她親眼看到：**同一個想法，在不同的框架下難度會改變**。

### Step 5 — 選一個要做的（5 min）

從「🟢 簡單」那堆裡，選一張她**最想做的**。

> ⚠️ 一定要從簡單那堆選。這是紀律。

### 💡 Teaching Tips

- 她如果想從「困難」選，溫和地問：「我們先把這個拆成兩三個小的，再看哪個是簡單的好不好？」
- 分類沒有「標準答案」。她覺得難就是難 — 這本身就是她的學習
- 如果她卡住，給她看 cheatsheet，提醒她「我們已經會做什麼」
- **這一幕結束時，她應該覺得：「原來我有好多想法，而且我知道哪個我真的做得到。」**

## 🎬 第三幕：選一個功能真的做出來（60–70 min）

**目標**：用 AI 把她**自己選**的那個功能做出來，體驗完整的「想法 → 可以用」。

### 活動流程

1. **她用自己的話描述要做什麼**
   - 不要用「技術語言」，就用白話
   - 例：「我希望每張卡片右上角有一個小星星，點下去會變金色」
2. **她把這段描述貼給 Antigravity / AI**
   - 你在旁邊看，不要動鍵盤
3. **AI 產出 code → 她存檔 → 看 localhost**
4. **如果壞了，她描述「哪裡不對」→ AI 再改**
5. **重複到她滿意為止**

### 核心原則

| ✅ 要做 | ❌ 不要做 |
|---|---|
| 她主導 prompt | 你幫她打字 |
| 她描述問題 | 你直接看 code 找 bug |
| 一起看 localhost | 你自己改完給她看 |
| 你提問引導她思考 | 你講解程式原理 |

### 💡 Teaching Tips

- 你的角色是 **guide**，不是 **coder**
- 她卡住時，問：「你覺得 AI 哪裡沒懂？你要怎麼再講一次？」
- 如果 AI 一直搞壞，幫她把問題拆得更小，但**還是讓她來講**
- 功能做出來的瞬間記得大聲慶祝 🎉 — 這份成就感就是她下次會繼續的理由
- **如果時間跑很快就做完了**：回到 Idea Sorting Board，再選一個簡單的做
- **如果快超時了**：完成到一個「能看到成果」的狀態就好，不用完美

## 🎬 第四幕：API 概念探索（20–25 min）

**目標**：讓她知道「app 可以跟別的服務對話」這件事 — **完全不用實作**。

### 活動流程

1. **用一句話開場**：
   > 「你知道你的 app 可以『打電話』跟別人家的服務要資料嗎？這個叫做 API。」

2. **用生活比喻**：
   - API = 去餐廳點餐：你給菜單編號 → 廚房給你菜
   - 你不用知道廚房怎麼做菜，只要知道怎麼點

3. **Demo：Google Calendar API（純看，不做）**
   - 打開 Google Calendar API Explorer（或 Jones 先準備好的截圖 / 影片）
   - 展示：送一個 request → 拿回一份 JSON → 裡面有她的行程
   - 讓她看到「原始資料長這樣」，但**不要解釋 OAuth、token、scopes**

4. **連回她的 DailyPlanner**：
   > 「你看，如果以後想把 Google Calendar 的行程顯示在你的 DailyPlanner 裡，就是去跟 Google 要這一份資料，再把它放進你現在的卡片就好。」

### 💡 Teaching Tips

- **完全保持概念層級**。一句 OAuth 都不要提
- 她可能會問：「那我們現在可以做嗎？」→ 回答：「可以，但那是下一堂課的事。今天我們是先知道『有這個東西』。」
- 目標不是讓她會用 API，是讓她**不再覺得 API 是黑魔法**
- 如果她興趣很高，記下來 — 下一堂課可以做一個「只讀」的整合

## 🎬 第五幕：收尾與反思（10–15 min）

**目標**：把整堂課的體驗沉澱下來，讓她帶走一個清楚的「下次怎麼開始」的心法。

### 活動流程

1. **回顧今天做了什麼**（2 min）
   - 「你今天產生了幾個想法？」
   - 「你自己選了哪一個？」
   - 「做出來的時候你的感覺是？」

2. **反思問題**（5 min）
   > 「如果禮拜天你自己一個人，想再加一個新功能，你會怎麼開始？」

   引導她講出：
   - 先想幾個點子
   - 排一下哪個簡單
   - 選一個簡單的
   - 用白話描述給 AI
   - 看 localhost、慢慢改

3. **記住這個循環**（3 min）

   在白板 / 紙上寫下，留給她：

   ```
   💡 想法  →  🗂️ 分類  →  🎯 選擇  →  🛠️ 實作
   ```

   > 「這是你以後做任何專案都可以用的。不只是 coding。」

4. **鼓勵 + 結束**（2 min）
   - 肯定她今天的主導性（「今天你是主角，我只是旁邊的人」）
   - 問她：下堂課想探索什麼？（記下來當作 Session 6 的種子）

### 💡 Teaching Tips

- 反思不是考試，是讓她**聽到自己講出來**
- 不要幫她總結，讓她用她自己的話講
- 最後一句話請真心誠意一點 — 她記得的不是你教了什麼，是她自己做到了什麼
